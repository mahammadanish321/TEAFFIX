TRACKING
========

After detection, we need multi-object tracking.

Explain:

Detection vs Tracking

YOLO tells us:

"There is a car here."

Tracking tells us:

"This is probably the SAME car I saw in previous frames."

Teach me:

- Track IDs
- Detection association
- IoU-based association
- ByteTrack
- Track lifecycle
- Track creation
- Track update
- Track disappearance
- Track confidence
- Why tracking is required for trajectory reconstruction

Example:

Frame 1:
Car → Track ID 17

Frame 2:
Car → Track ID 17

Frame 3:
Car → Track ID 17

Frame 4:
Car → Track ID 17

This gives us a local trajectory inside one camera.


LOCAL TRACK ID
==============

Our AI pipeline should generate a local track ID such as:

CAM_001_T_73

This ID is only meaningful inside the camera.

IMPORTANT:

local_track_id != global_vehicle_id

Example:

Camera A:
CAM_001_T_73

Camera B:
CAM_002_T_18

These could actually be the SAME physical vehicle.

Person 2's Re-ID / identity system and the Backend will eventually help determine that.


ANPR + PERSON 2 INTEGRATION
===========================

Person 2 handles:

- License plate recognition
- OCR
- Vehicle appearance embedding
- Re-identification
- Cross-camera identity matching

My pipeline should therefore be designed so that it can pass vehicle observations to Person 2.

Do not duplicate Person 2's responsibilities unnecessarily.

We should define a clean internal interface between Person 1 and Person 2.

Example concept:

VehicleObservation

{
    camera_id,
    local_track_id,
    timestamp,
    vehicle_type,
    bounding_box,
    confidence,
    frame_reference
}

Person 2 can enrich this with:

plate_number
plate_confidence
vehicle_embedding
embedding_model
embedding_version

Then the combined result becomes a Detection Event.
